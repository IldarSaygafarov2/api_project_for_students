# bozor.uz — фронтенд доски объявлений (демо)

Статичный сайт на чистом HTML/CSS/JS, спроектированный по образцу OLX.uz для
рынка Узбекистана. Готов к подключению к Django REST API — см. раздел ниже.

## Как открыть

Просто откройте `index.html` в браузере — сайт не требует сборки, npm или
сервера. Для корректной работы Geolocation API некоторые браузеры требуют
открытия через `http://`, а не `file://` — в этом случае запустите любой
статический сервер, например:

```
python3 -m http.server 8000
```

и откройте `http://localhost:8000`.

## Данные теперь вшиты статически в HTML

Раньше главная, каталог, карточка товара и т.д. были пустыми `<div id="...">`,
которые JS заполнял при загрузке страницы. Теперь весь контент — категории,
объявления, фильтры, личный кабинет — находится прямо в HTML-коде каждой
страницы, как это будет выглядеть после рендера Django-шаблона. JS остался
только там, где без него не обойтись: клики, фильтрация, модалки, форма
добавления объявления, чат.

Собрано это скриптом `tools/build-static.js` — он читает `js/data/*.js` и
вставляет реальную разметку прямо в `.html`-файлы. Если поменяете моковые
данные (например, добавите объявление в `js/data/listings.js`), запустите
его заново, чтобы вшить свежие данные:

```
node tools/build-static.js
```

Скрипт идемпотентен только на "чистой" версии файлов (там, где ещё стоят
исходные пустые `<div id="...">`) — если вы уже вручную правили сгенерированный
HTML, проще воссоздать нужный кусок руками, чем гонять скрипт повторно.

Несколько страниц (карточка товара, профиль продавца, «Написать продавцу»)
всегда завязаны на конкретный `?id=` — для них "вшитым" сделан только один
пример (обычно объявление №1 / продавец u1), а JS по-прежнему умеет
перерисовать блок для любого другого id. В Django это будет не нужно —
там каждый такой URL сразу отрисовывается сервером под конкретный объект.

## Подключение к Django

Всё общение с «сервером» уже собрано в одном файле — `js/api.js`. Ни одна
другая страница не обращается к моковым данным или localStorage напрямую,
поэтому подключение реального бэкенда — это правка одного файла:

1. Поднимите Django + Django REST Framework, реализуйте эндпоинты, на которые
   уже есть намётки прямо в комментариях `api.js`:
   - `GET /api/categories/`, `GET /api/regions/`
   - `GET /api/listings/?category=&region=&min_price=&max_price=&condition=&q=&sort=&page=`
   - `GET /api/listings/{id}/`, `POST /api/listings/`
   - `POST /api/auth/login/`, `POST /api/auth/register/`, `POST /api/auth/google/`
   - `GET/POST /api/favorites/`, `GET/POST /api/conversations/`
2. В `js/api.js` задайте `const API_BASE = 'https://ваш-домен/api';` и замените
   тело каждой `apiXxx()`-функции на `fetch(...)` — сигнатура вызовов и форма
   возвращаемых данных уже подобраны так, чтобы остальной код не пришлось
   переписывать.
3. Замените локальную «сессию» (localStorage) на настоящую — JWT в заголовке
   или сессионную cookie Django. Для входа через Google подключите Google
   Identity Services (`accounts.google.com/gsi/client`), полученный
   `id_token` отправляйте на `POST /api/auth/google/`, где Django проверит
   его через `google-auth` и создаст/найдёт пользователя.
4. Замену фото с `data:` URL на реальную загрузку файлов удобнее всего сделать
   через `FormData` в `apiCreateListing`.

## Ограничения текущей демо-версии

- Данные (объявления, избранное, сообщения, сессия) хранятся в `localStorage`
  браузера — это заметно только на одном устройстве и пропадёт при очистке
  данных сайта.
- «Мои объявления» в личном кабинете условно привязаны к демо-продавцу `u1`
  из моковых данных — при подключении Django это будет `request.user`.
- Вход через Google и отправка формы — имитация (подробности см. в
  `js/auth.js`), поскольку настоящий OAuth требует Client ID и бэкенд для
  проверки токена.
